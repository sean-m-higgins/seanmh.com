Phase 1 — Cinematic In-Cluster Switching COMPLETE

  1. Delivered switcher kit: a byte-identical universe dial component and transition stylesheet on content plus the three portfolio branches.
  2. Shared anchors: the Sean name headline and universe dial morph across documents; the rest crossfades with terminal CRT, card tilt, and scroll-rise flavor.
  3. Progressive enhancement: unsupported browsers navigate normally; prefers-reduced-motion disables the animation layer.
  4. Worker behavior: forced ?v= selection and document navigations refresh the pv cookie; asset/fetch responses do not overwrite a new selection.
  5. July 25 follow-up: ARIA state, Escape-to-close/focus restoration, and a non-link active item are committed byte-identically on all four canonical branches, one commit ahead of origin.
Remaining verification: deliberate real-browser pass for the cross-document morph, fallback navigation, touch expansion, and reduced motion. Headless automation is not reliable for the arrival animation itself.

Phase 2 — Make the Terminal Real COMPLETE

  1. Command engine: real prompt, portfolio/content commands, generated git history, version switching, history, tab completion, and unknown-command handling are implemented.
  2. ask <question>: the Worker handles /api/ask before proxying and streams Claude Sonnet 5 output grounded in client context plus optional server-side KV context.
  3. Guardrails: shared-secret gate, server-only API key, soft per-IP KV limit, question/output caps, and an about-Sean-only system scope.
  4. Resilience: the terminal falls back to a local grounded answer if the remote endpoint or its infrastructure is unavailable.

Phase 3 — The Shiny Button, the Bridge & Cluster 2's First Page NOT STARTED

  1. Worker v2 — cluster model: config becomes two clusters. pv cookie still picks within Cluster 1 on first visit; a visitor's current page determines which "adjacent" versions the dial offers. Cluster 2 is never randomly assigned — it's only reachable through the button (it should feel like a discovery).
  2. The shiny button: one irresistible artifact in all Cluster-1 versions (glowing orb in the corner; in the terminal it's a mysterious ??? command that help hints at). Subtle idle animation, stronger pull on hover.
  3. The bridge transition: deliberately different from in-cluster morphs — a warp/iris-wipe (View Transition types: ['bridge']) so crossing clusters feels like leaving the universe, not flipping a page. Same effect in reverse to come home.
  4. Cluster 2 page #1 — The Hall of Versions (version/d-hall): gallery of AI-generated site designs; each entry = screenshot, generation #, date, and the prompt that created it. Ships with generation #1 created interactively with Claude Code.
  5. Self-redesign pipeline: monthly scheduled Claude Code cloud agent (or GitHub Action): pick a style direction → generate a full standalone design as gen/N branch → open PR with preview link. On merge: deploy, screenshot, append to the hall manifest. Human approval stays in the loop — a PR you review.

The Nexus now exists independently, so Phase 3 can use it as the first bridge destination while the Hall and redesign pipeline are built. A formal two-cluster data model is still optional until more than one playground page exists.

Risks & Mitigations

  • Cross-document View Transitions aren't universal
  • → Treat as enhancement; fade fallback everywhere; feature-detect, never block navigation.
  • Claude API cost/abuse on ask
  • → Shared-secret gate, KV rate limit, token caps, server-only key, monthly spend monitoring.
  • Six+ deployments drifting out of sync
  • → Keep the switcher kit strictly synchronized; treat a-scroll's newer content/schema as an intentional divergence that requires manual ports.
  • Nexus bloating load time
  • → Current main scene chunk is ~131 KB gzip. Keep the 1 MB ceiling, code-split if the scene grows, and do not add it to random assignment.
