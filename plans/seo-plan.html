seanmh.com — Search Visibility Plan

Goal: rank seanmh.com for the owner's own name. Diagnosed against the live site and all version branches on July 29, 2026. Revised August 17, 2026 against worker.js: rotation is gone, and two game origins have been added since.

Goal: when someone searches for Sean M Higgins, seanmh.com is the result they find. Target the qualified queries first — "Sean M Higgins" and "Sean Higgins software engineer" — and treat the bare "Sean Higgins" query as a long game against several established namesakes.

Diagnosis

✓ Homepage stabilized

Random rotation is gone as of e91e744. / now resolves ?v= → pv cookie → a-scroll, so a cookie-less crawler always sees a-scroll.

✗ Documents still uncacheable

private, no-store is unchanged on every document response. The one remaining half of the original homepage problem.

✗ Origins outrank the domain

seanmh-scroll.pages.dev is what actually surfaces in search — not seanmh.com. Now six crawlable origins, up from four: the two game branches were added since this plan was written.

✗ No entity markup

No Person JSON-LD in any branch. Nothing tells Google the page is the entity being searched for.

✗ Never submitted

No Google Search Console verification and no analytics. Google was never told the site exists, and there is no view of what it sees.

✗ Thin surface area

The sitemap contains exactly one URL. One page is very little to rank, and there are no supporting content pages.

✗ No social image

No og:image or twitter:image, so shared links render bare. A headshot already exists, unused, on content.

Evidence

Version resolution in worker.js as of e91e744 — deterministic, with no randomness left in the path:

?v=<name>  → that version, and refresh the pv cookie   (explicit human choice)
pv cookie  → that version                              (sticky, Max-Age=1800)
neither    → a-scroll                                  (DEFAULT_VERSION)

every document response → cache-control: private, no-store   ← still open

The default is stable for humans and crawlers alike rather than a user-agent carve-out, so it is not cloaking. Decision — resolved August 16, 2026

Rotation and a stable search identity were mutually exclusive, and the recommendation was taken. a-scroll is the stable default at /; the version switcher is now the discovery mechanism for the other five. Explicit choice survives via ?v= and the sticky pv cookie — it simply stopped being what a crawler sees. Shipped in e91e744.

The cloaking alternative — serving a stable version to crawler user agents only — was considered and explicitly rejected in the commit: the default is the same for humans and crawlers. The commit also cites a second benefit beyond indexing, that Core Web Vitals field data for / is no longer an unattributable mix of three separate codebases.

Nothing in this plan is blocked on a decision any more. The remaining queue is execution.

Next steps — single TODO queue

  1. ✓Stabilize what the crawler sees at /. — Shipped e91e744, August 16, 2026. Cookie-less visitors now get a-scroll instead of a random pick; ?v=, the switcher, and cookie stickiness are untouched. scripts/dev-proxy.mjs mirrors the same resolution so local dev lands where production does, and test/worker.test.js locks the behavior in.
  2. P0Make documents cacheable. Now the only thing standing between / and a clean crawl. Replace the private, no-store at worker.js:40 with a short revalidating policy so the apex can be cached and snapshotted. The cookie interaction is the thing to get right: the Worker appends Set-Cookie on every document response, so any shared-cache policy must stay private or vary correctly — a cached document must never pin a visitor to the wrong version. Extend the Worker test suite to assert the header on both a default and a ?v= response.
  3. P0Deindex the *.pages.dev origins — six of them now. Add X-Robots-Tag: noindex via a Pages _headers file on version/a-scroll, b-card, c-terminal, nexus, d-3d-game, and e-2d-game, then strip that header in the Worker for proxied responses. Net effect: origins drop out of the index while seanmh.com stays fully indexable. Add the missing canonical to Nexus. Verify with a header check against each origin and the apex. Note the standing cost: every new version branch adds a crawlable origin, so this needs to become part of shipping a version, not a one-time sweep.
  4. P0Register with Google Search Console. Verify the domain, submit sitemap-index.xml, request indexing for /, and use URL Inspection to confirm Google renders a-scroll. With rotation gone this check is now meaningful — a mismatch points at a real bug rather than a coin flip. This is also the only reliable way to observe the rest of this queue working.
  5. P1Add Person structured data. One JSON-LD block in each layout: name, alternateName: "Sean M Higgins", url, jobTitle, alumniOf: Loyola University Chicago, and sameAs pointing at LinkedIn, GitHub, and X. This is the highest-leverage single on-page change for a name query. Validate with the Rich Results Test.
  6. P1Ship a real social card. Add og:image and twitter:image using the unused headshot.jpeg on content, upgrade twitter:card to summary_large_image, and give each version its own variant so a shared link reflects what the visitor will land on.
  7. P1Claim the entity off-site. Link seanmh.com from the LinkedIn profile, the GitHub profile and profile README, and the X bio. Google confirms an entity by reciprocity — sameAs pointing outward with nothing pointing back is an unsupported claim. Likely the highest-value item in this queue, and the only one that is not a code change.
  8. P2Grow indexable surface area. Publish the fifteen wiki/ technical write-ups as real /projects/* pages with their own titles, descriptions, and sitemap entries. Turns a one-URL site into a body of substantive, on-topic content that corroborates the entity.
  9. P3Decide the AI-crawler posture. The managed robots.txt currently blocks ClaudeBot, GPTBot, and Google-Extended. Given how often people now look someone up through an assistant, decide deliberately whether to keep AI training blocked while allowing retrieval, and document the reasoning either way.
